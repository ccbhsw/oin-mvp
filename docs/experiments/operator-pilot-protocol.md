# 最小独立 Operator 试点协议（草案）

## 目的与前提

本协议用于检验 OIN 的签名描述符、Bootstrap、复制、恢复与成本假设是否能在**两个互不隶属的真实参与者**之间成立。它不是招募已经完成的证明，也不是生产部署说明；在候选机构书面同意前，不得声称存在真实 Operator 或真实保留承诺。

> 试点的核心问题不是“能否运行两个节点”，而是“两个具有不同利益、基础设施和退出路径的机构，是否愿意且能够持续保存明确授权的信息，并在一方退出后保留可验证历史”。

## 准入与排除标准

| 类别 | 最低要求 | 排除条件 |
| --- | --- | --- |
| 机构独立性 | 不同直接管理员、托管账户或自治域；记录资金、域名与人员重叠。 | 同一人控制两节点，或仅用同一云账户/同一凭据伪造双节点。 |
| 保存动机 | 每方明确本机构的资料、研究、公共使命或服务收益。 | 仅因“挖矿”、代币预期或无明确维护责任加入。 |
| 样本授权 | 仅使用双方已明确拥有或获许可保存与复制的公开样本。 | 个人敏感信息、未授权抓取内容、受争议保密资料、受限访问材料。 |
| 安全运行 | 私钥独立保存；端点不直接暴露无认证的开发 API。 | 共用私钥、公开开发端口或把凭据写入 Bundle。 |
| 时间承诺 | 30 天观测期内指定至少一名维护联系人。 | 无人负责升级、故障或退出演练。 |

## 分阶段执行

| 阶段 | 动作 | 成功证据 | 失败判定 |
| --- | --- | --- | --- |
| 0. 书面范围 | 双方确认样本、保留期、用途、成本记录方法及联系人。 | 双方范围声明；不含秘密与个人数据。 | 无法确定授权或保留责任。 |
| 1. 自主部署 | 各自独立初始化身份与数据目录，发布显式配置的 Descriptor。 | 两份可独立验签 Descriptor；共同失败域清单。 | 共用密钥、共用管理账户或描述符无法验证。 |
| 2. Bootstrap 交换 | 人工互换静态 Bundle，双方从自身节点读取 `/v1/discovery/peers`。 | Bundle 中对方描述符验签且未过期。 | 端点投毒、过期或来源不可解释。 |
| 3. 明确复制 | 由双方管理员显式执行现有 replication 流程，导入已授权样本。 | 两端归档哈希、签名和离线验证均通过。 | 验证失败、未授权复制或无法记录来源。 |
| 4. 运行测量 | 连续 30 天记录存储、出站、工时、告警、修复和每次验证。 | 完整成本账本与事件日志。 | 无法取得成本或维护数据。 |
| 5. 退出与恢复 | 一方停止服务并导出可携带包；另一方继续验证历史并按约定恢复。 | 独立离线验证、恢复证明与退出记录。 | 退出使历史不可读、不可验证或不可迁移。 |

## 最小测量账本

每个 Operator 应按周填写以下**聚合**指标，不上传日志、凭据、IP 地址或未获许可的内容。

| 指标 | 单位 | 说明 |
| --- | --- | --- |
| 活跃归档字节 | GiB | 本地已验证保存的归档总量。 |
| 副本数量 | 整数 | 本节点保留的已验证 Observation 数。 |
| 出站/入站字节 | GiB | 仅记录总量，用于估算网络成本。 |
| 人工工时 | 小时 | 配置、排障、元数据、合规与恢复分别记录。 |
| 验证失败数 | 整数 | 以失败原因分类；不以失败内容做公开展示。 |
| 修复时间 | 小时 | 从检测到恢复后离线验证成功的时间。 |
| 月度直接成本 | 本地货币 | 存储、带宽、支持、法律/合规咨询分开记录。 |
| 留存意愿 | 是/否/待定 | 30 天后是否愿意继续及条件，不推断为承诺。 |

## 预注册的判定规则

试点仅在同时满足下列条件时称为“技术与参与价值初步成立”：两方独立身份和 Descriptor 可验签；至少一个已授权样本在两方均通过离线验证；一方退出后另一方仍可验证并导出；双方均能报告成本；且至少一方能明确说明继续保存的非投机性价值。

若任何一项不成立，报告必须记录 **FAILED ASSUMPTION** 或 **PARTIAL PASS**，而不是用节点数量、演示截图或单次复制掩盖失败。试点不测试身份轮换、数据删除、法律保留或治理投票；这些分别受红灯决策与法律审查约束。

## 交付物

试点完成后应产生：双方签名 Descriptor 的公开副本；经脱敏的 Bundle；复制与恢复的离线验证输出；聚合成本账本；共同失败域矩阵；退出/恢复报告；以及由双方审阅的实验结论。所有材料都应明确样本授权范围和不能证明的内容。
